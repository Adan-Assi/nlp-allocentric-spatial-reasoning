# Project Update: RVS Manhattan Navigation & Underspecification

## 1. Overview
We have successfully built a pipeline that bridges **Natural Language Instructions** with the **Manhattan Road Network**. Our current system can parse the environment, identify key landmarks, and generate "degraded" (underspecified) instructions to test LLM reasoning.

---

## 2. Key Discovery: The "Metadata vs. Content" Gap
When looking at our data (e.g., Sample #316), we noticed a large number of `main_pivots` (up to 15+) in the JSON that **do not** appear in the instruction text.

### Why the discrepancy?
* **The "Sensor" Scan:** The RVS dataset was generated by "walking" a path in the graph. As the simulator walks, it logs *every* landmark it passes (e.g., `FDNY Ladder 8`, `Duarte Square`).
* **The "Selection" Step:** To keep instructions human-readable, the generator only selects a **subset** of these landmarks (usually the `near_pivot` or a specific `main_pivot`) to put into the "content" field.
* **Our Strategy:** Our masking script correctly targets only the landmarks actually mentioned in the text, ensuring our experiments are realistic.



---

## 3. Completed Components

### `scripts/rvs_parser.py`
**Role:** The Data Loader.
* Loads the Manhattan road graph (`.gpickle`).
* Pairs each instruction with its ground-truth coordinates and landmark metadata.
* **Result:** 7,000 verified samples ready for processing.

### `scripts/underspecify_instructions.py`
**Role:** The Experiment Generator.
* Uses the `landmarks` metadata to find strings in the text and replace them with `[MASK]`.
* Uses Regex to replace cardinal directions (North, South, etc.) with `[DIR_MASK]`.
* **Result:** A new dataset (`underspecified_variants.json`) containing 500+ test cases.

### 3.1 Experimental Variants: "Hard Mode"
We have added a `mask_both` variant to the generation script. 

* **Definition:** This removes both the landmarks and the cardinal directions simultaneously.
* **Purpose:** To determine the "absolute floor" of spatial reasoning. Can a model find a destination using only block distances and street endings?
* **Current Status:** These are generated and stored in `underspecified_variants.json`, but we will **skip** evaluating them until our baseline (Single-Mask) tests are finished.

**Metadata (The "Cheat Sheet"):**
* `near_pivot`: `["church", [40.710, -74.013]]`
* `goal_node`: `[40.710, -74.013]` (The Garden)

**Our Generated Variants:**
1. **`mask_near`**: "...Just south is a **[MASK]**."
2. **`mask_directions`**: "...Just **[DIR_MASK]** and across the street to the **[DIR_MASK]** is a church."

## 5. Next Phase: The Symbolic Oracle
Our next task is building the **Oracle Solver**. It will act as the "Ground Truth" for our experiment.

**The Logic:**
1. Take a masked instruction (e.g., "The garden on Liberty Street").
2. Search the `manhattan_graph.gpickle` for all nodes matching "Garden" + "Liberty Street".
3. **Labeling:** - If only **one** garden exists: Label as **Answerable**.
   - If **multiple** gardens exist (because we masked the church that distinguished them): Label as **Ambiguous**.
